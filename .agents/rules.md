# Rules

Coding, testing, and workflow conventions specific to this project. Static rules live here; the agent updates them when conventions change.

## Source of Truth: Methodichkas

- The **baseline** for code, object names, attribute names, UI steps, and order of operations is the teacher's methodical instructions (PDF) shipped with each lab.
- Location: `labN/src/*.pdf` (e.g. `lab3/src/Лабораторная работа №3 (2022-2023).pdf`). They are intentionally not versioned — `lab*/` is gitignored.
- **Code in these PDFs is images, not text.** `pdftotext` returns zero `Процедура` / `Функция` matches; the listings are screenshots. Render the page to PNG and read it with vision.
- Reproduce the printed code as the starting point: same structure, same order, same logic.
- **Allowed deviations** (still anchored to the methodichka):
  - renames required by the variant — procedure, function, variable, object names;
  - literal and value changes required by the variant;
  - small fixes needed to make the printed code actually run in this configuration.
- **Forbidden:** adding functionality, objects, attributes, checks, or algorithms that the methodichka does not describe; restructuring the solution; "improving" code that already works.
- If a step is missing, ambiguous, or the image is unreadable — stop and ask the user. Do not fill gaps from general 1C knowledge.
- Cite the source in the answer: file name and page number.
- The teacher penalizes unauthorized additions, even when they are technically better. Variant-driven edits are fine; self-invented features are not.

## Code Style

- No application code in this repo. Scripts are the installed skills (Python) and shell one-liners.
- Shell: POSIX `bash`/`zsh`, no GNU-only flags (`timeout` is absent; `gtimeout` only if coreutils is installed).
- Python: 3.13, standard library plus `lxml`, `Pillow`, `psutil`.

## Languages

- User-facing UI text: Russian.
- Identifiers, file names, commits, docs: English.

## Design

- No UI design work. The configuration XML in `lab*/src` is the source of truth.
- Do not hand-edit XML if a skill can do it: `meta-edit`, `form-edit`, `skd-edit`, `role-edit`, etc.

## State and Persistence

- `.v8-project.json` — database registry (paths, credentials, default base).
- `.opencode/1c-testpilot.profiles.yaml` — launch profiles for the test client.
- `.opencode/opencode.json` — MCP servers, project scope only.
- All three may contain credentials. Do not commit them if the workspace becomes a git repo.

## Testing

- No test framework. Verification is running the skill against a real base:
  - `cf-info` against `lab3/src` for XML parsing;
  - `DESIGNER /DumpConfigToFiles` against each base for batch mode;
  - `tc_session(launch_client)` + `stop_client` for the live client.
- Always stop launched 1C clients after verification (`tc_session(action="stop_client")` or `pkill -f 1cv8`).

## Generated and External Files

- `.opencode/skills/**` — copied from `cc-1c-skills`; do not edit in place, update the upstream copy instead.
- `lab*/1Cv8.1CD`, `*.cfl`, `1Cv8Log/` — platform-managed; never edit by hand.
- `lab*/src/**` — generated by `db-dump-xml`, edited by skills, then loaded back with `db-load-xml`.

## 1C Specifics

- Batch designer commands must end with `-DisableStartupDialogs`, otherwise a dialog can block the process.
- Never pass `/P` with an empty value; omit it.
- Credentials: lab1 none, lab2 `админ`, lab3 `admin`.
- Use the symlinks `~/.local/1cv8/8.3.27.1606/1cv8` and `1cv8c`; never the `/Applications` stubs.

## Git

- Do not commit, push, create PRs, or run destructive git operations without explicit user request.
- Before any commit (if requested): check `git status`, `git diff`, `git log --oneline -10`; stage only intended files.
- Remote: `origin` = `git@github.com:gz0ni/1c-mcp-bundle.git`, branch `main`.
- Never stage `lab*/`, `test/`, `.v8-project.json`, `.opencode/opencode.json`, or `.opencode/1c-testpilot.profiles.yaml` — they are gitignored for a reason.
